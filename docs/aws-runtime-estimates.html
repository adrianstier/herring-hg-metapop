Expected AWS Runtime for Herring Model Farm

Updated May 10, 2026. Estimates are wall-clock per submitted AWS Batch job after container startup and Stan compilation. AWS mainly improves throughput by running branches in parallel.

Model / Task Purpose Local Reference Expected AWS Runtime Risk How to Run
Smoke fit Verify image, S3 bundle, R/rstan interface, Stan compile, and result upload. Short 1-chain reduced iteration run. 20-60 minutes Low Run first on Spot. Do not submit the full farm until this passes.
M1 observation branches Baseline Stier-style observation/detection variants; best current family for fit diagnostics. m1_stier_11 roughly 3.5-3.6 h locally. 2-5 hours each Low to medium Good first full candidates. Run several variants in parallel.
M2 site-growth Site-specific growth/productivity extension. m2_stier_site_growth roughly 3.0 h locally. 2-5 hours Medium Run after smoke. Compare against M1 on diagnostics, not only LOO.
M3 spatial distance Spatially structured process error / distance-decay branch. m3_stier_distance roughly 4.5-4.7 h locally. 3-8 hours Medium Run on Spot first; promote only if sampler-clean.
Exact re-LOO array Refit problematic observations for reliable model comparison. Expensive if serial on laptop. 2-8 hours per array child; wall time near the slowest child Medium Strong AWS use case because children are independent.
Predator / time-varying branches Predator covariates, climate interactions, or more complex process structure. Older m5_v3 was pathological and ran 14-32 h per chain locally. 6-24+ hours High Exploratory only until observation model is stable; use Spot and tight smoke tests.
Laptop closure rule: after the image is pushed and AWS Batch has accepted job IDs, cloud jobs keep running if the laptop sleeps. The laptop is still needed to submit more jobs, monitor, download results, and rerun follow-up branches.
